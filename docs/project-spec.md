# Quest Fitness — живая спека проекта

> **Назначение:** единый ориентир по цели, направлению и ограничениям.  
> Канон требований продукта: PRD `final` ниже. Этот файл — краткий якорь + процесс.

**Статус:** планирование Скелета готово → реализация  
**Последнее обновление:** 2026-09-29

---

## 1. Цель

Внутренний **веб**-инструмент одного зала: пул тренеров + пул клиентов, дневник, live-сессии, программы. Клиенты зала смотрят свой кабинет. Не SaaS и не биллинг.

## 2. Техрамки

| Решение | Выбор |
|--------|--------|
| Платформа | Веб-приложение, mobile-first |
| Frontend | React + TypeScript |
| Backend | отдельный сервис (стек — architecture) |
| Репозиторий | `frontend/` + `backend/` |
| API | BFF |

## 3. Процесс

Оркестратор (тяжёлая модель) → чёткие задачи сабам без додумывания. **TDD:** тест → red → код. Техвопросы — отдельно. Спека/PRD — якорь контекста.

## 4. Продукт (кратко)

- Роли: Клиент / Тренер / Админ (админ = тренер + привилегии)
- Общие пулы; нет «ответственного тренера»; эксклюзивная работа с клиентом (TTL 30 мин бездействия + «Освободить»)
- Скелет: шаблоны, макроциклы (поэтапно), расписание, live (таймер тренировки + отдых, суперсеты, модификаторы), дневник в БД, регистрация по ссылке (TTL 1 день)
- Этап 2: аналитика, питание, замеры, ачивки+ранг, абонементы (CRUD планов — админ)
- Auth клиента: регистрация (имя, телефон, логин, пароль) → вход логин\|телефон + пароль
- Дизайн: Гильдия — `docs/design-refs/`, design-brief в PRD workspace
